# Laboratory 09 Reflection: Cloud Automation Engineer

This laboratory helped me understand how automation can make cloud operations faster and more consistent. When managing hundreds of cloud servers, performing tasks manually takes a lot of time and can lead to human errors. Automation allows administrators to repeat tasks, such as backups, using scripts and scheduled jobs.

However, automation also has risks. A small mistake in a script can cause serious problems, especially if it runs on hundreds or thousands of servers. For example, a destructive command with the wrong path could delete important files. Because of this, scripts should be reviewed and tested carefully before they are scheduled or deployed to many systems.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. In this activity, I used Bash commands, variables, and a timestamp to create compressed backups. Docker Compose, on the other hand, uses YAML to describe how containers and related services should run together. Both tools help automate work, but they are designed for different purposes.

Looking back at my GitHub portfolio from Laboratory 1 to Laboratory 9, I can see how my understanding of cloud computing has grown. I started by learning basic cloud concepts and gradually explored infrastructure, cloud platforms, containers, deployment, operations, security, and automation. These activities helped me understand that cloud computing involves more than simply running applications; it also requires managing resources, protecting systems, and maintaining reliable services.

The role I enjoyed most was the Cloud Automation Engineer because I found it useful to create a script that performs a task automatically. Learning how to schedule backups showed me how small improvements can save time and help prevent forgotten tasks. I want to continue improving my Linux and cloud administration skills so I can apply them to future IT projects.
